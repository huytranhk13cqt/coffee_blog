## 1. Skills Là Gì?

### Định Nghĩa Đơn Giản

**Skills** là các "gói chuyên môn" giúp Claude trở nên giỏi hơn trong những tác vụ cụ thể.

**Hãy tưởng tượng như thế này:**

- Claude giống như một nhân viên mới rất thông minh
- Skills giống như "tài liệu đào tạo" cho nhân viên đó
- Khi cần làm việc gì đó chuyên biệt, Claude sẽ đọc tài liệu phù hợp

### Skill Bao Gồm Gì?

```
my-skill/
├── SKILL.md          # 📄 File BẮT BUỘC - Hướng dẫn chính
├── reference.md      # 📚 Tài liệu tham khảo (tùy chọn)
├── examples.md       # 💡 Ví dụ minh họa (tùy chọn)
└── scripts/          # 🔧 Code hỗ trợ (tùy chọn)
    └── helper.py
```

### So Sánh Dễ Hiểu

| Không Có Skill                   | Có Skill                                     |
| -------------------------------- | -------------------------------------------- |
| Claude làm theo cách chung chung | Claude làm theo quy trình chuẩn của bạn/team |
| Bạn phải giải thích lại mỗi lần  | Claude tự động biết cách làm                 |
| Kết quả không nhất quán          | Kết quả đồng nhất, chuyên nghiệp             |

## 2. Tại Sao Cần Dùng Skills?

### Lợi Ích Chính

1. **Tiết Kiệm Thời Gian**: Không cần giải thích lại quy trình mỗi lần
2. **Kết Quả Nhất Quán**: Claude luôn làm đúng cách bạn muốn
3. **Chia Sẻ Được**: Team có thể dùng chung Skills qua Git
4. **Kết Hợp Được**: Nhiều Skills có thể làm việc cùng nhau

### Khi Nào Nên Tạo Skill?

✅ **Nên tạo Skill khi:**

- Bạn làm việc gì đó lặp đi lặp lại
- Team cần tuân theo quy trình chuẩn
- Cần xử lý file/document theo format cụ thể
- Muốn Claude nhớ các quy tắc đặc biệt

❌ **Không cần Skill khi:**

- Chỉ làm một lần duy nhất
- Tác vụ đơn giản, Claude đã biết cách làm
- Không có quy trình cố định

## 3. Cách Skills Hoạt Động

### Progressive Disclosure (Tiết Lộ Từng Bước)

Skills không load tất cả vào bộ nhớ ngay. Thay vào đó, Claude load theo 3 cấp độ:

```
┌─────────────────────────────────────────────────────────────┐
│ Level 1: METADATA (Luôn load)                               │
│ → Chỉ name + description (~100 tokens/skill)                │
│ → Claude biết skill tồn tại và khi nào dùng                 │
└─────────────────────────────────────────────────────────────┘
                              ↓
                    (Khi user request liên quan)
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ Level 2: INSTRUCTIONS (Load khi cần)                        │
│ → Nội dung chính của SKILL.md (<5k tokens)                  │
│ → Hướng dẫn, workflows, quick start                         │
└─────────────────────────────────────────────────────────────┘
                              ↓
                    (Khi cần chi tiết hơn)
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ Level 3: RESOURCES (Load theo nhu cầu)                      │
│ → Files bổ sung: reference.md, examples.md                  │
│ → Scripts: chạy mà không cần load code vào context          │
└─────────────────────────────────────────────────────────────┘
```

### Ví Dụ Thực Tế

```
User: "Tạo commit message cho changes này"

1. Claude scan metadata của tất cả skills
2. Thấy skill "commit-helper" phù hợp (từ description)
3. Load nội dung SKILL.md của commit-helper
4. Làm theo hướng dẫn trong đó
5. Nếu cần examples → load examples.md
```

## 4. Cấu Trúc Của Một Skill

### File SKILL.md (BẮT BUỘC)

```yaml
---
name: ten-skill-cua-ban
description: Mô tả ngắn gọn skill làm gì và khi nào dùng
---

# Tên Skill

## Instructions
Hướng dẫn từng bước cho Claude

## Examples
Ví dụ cụ thể
```

### Quy Tắc Đặt Tên

| Field         | Quy Tắc                                         | Ví Dụ                                                                |
| ------------- | ----------------------------------------------- | -------------------------------------------------------------------- |
| `name`        | Chỉ lowercase, số, dấu gạch ngang. Max 64 ký tự | `commit-helper`, `pdf-processing`                                    |
| `description` | Max 1024 ký tự. Mô tả rõ ràng                   | `Generate commit messages from git diffs. Use when writing commits.` |

### Cấu Trúc Thư Mục

**Skill Đơn Giản:**

```
commit-helper/
└── SKILL.md
```

**Skill Phức Tạp:**

```
pdf-processing/
├── SKILL.md              # Hướng dẫn chính
├── FORMS.md              # Hướng dẫn điền form
├── REFERENCE.md          # API reference
├── examples/
│   ├── basic.md
│   └── advanced.md
└── scripts/
    ├── extract_text.py
    ├── fill_form.py
    └── validate.py
```

## 5. Cách Tạo Skill Đầu Tiên

### Bước 1: Chọn Vị Trí Lưu

**Personal Skills** (chỉ bạn dùng):

```bash
# Tạo thư mục
mkdir -p ~/.claude/skills/my-first-skill
```

**Project Skills** (cả team dùng):

```bash
# Trong thư mục project
mkdir -p .claude/skills/my-first-skill
```

### Bước 2: Tạo File SKILL.md

```bash
# Mở editor
code ~/.claude/skills/my-first-skill/SKILL.md
```

### Bước 3: Viết Nội Dung

```yaml
---
name: my-first-skill
description: Brief description of what this does. Use when [specific trigger].
---

# My First Skill

## Quick Start

[Hướng dẫn nhanh nhất để bắt đầu]

## Instructions

1. Step 1: ...
2. Step 2: ...
3. Step 3: ...

## Examples

**Input:** [Ví dụ đầu vào]
**Output:** [Ví dụ đầu ra mong muốn]
```

### Bước 4: Test Skill

Mở Claude Code và hỏi câu liên quan đến skill:

```
claude
> [Hỏi câu gì đó match với description của skill]
```

## 6. Viết SKILL.md Hiệu Quả

### Nguyên Tắc Vàng: NGẮN GỌN

Claude đã rất thông minh. Chỉ viết những gì Claude CHƯA biết.

**❌ Xấu (quá dài dòng):**

```markdown
PDF (Portable Document Format) là định dạng file phổ biến
chứa text, hình ảnh và nội dung khác. Để trích xuất text
từ PDF, bạn cần dùng library. Có nhiều library như pypdf,
pdfplumber, PyMuPDF... Chúng tôi recommend pdfplumber vì
nó dễ dùng...
```

**✅ Tốt (ngắn gọn):**

````markdown
## Extract PDF text

Use pdfplumber:

```python
import pdfplumber

with pdfplumber.open("file.pdf") as pdf:
    text = pdf.pages[0].extract_text()
```
````

### Viết Description Hiệu Quả

Description quyết định Claude có tìm thấy skill không!

**❌ Xấu (quá chung chung):**

```yaml
description: Helps with documents
```

**✅ Tốt (cụ thể + trigger):**

```yaml
description: Extract text and tables from PDF files, fill forms, merge documents. Use when working with PDF files or when the user mentions PDFs, forms, or document extraction.
```

**Template cho Description:**

```
[Làm gì - động từ + đối tượng]. Use when [khi nào dùng/trigger words].
```

### Cấu Trúc SKILL.md Chuẩn

```yaml
---
name: skill-name
description: [Làm gì]. Use when [khi nào dùng].
---

# Skill Name

## Quick Start
[1-2 câu + code example đơn giản nhất]

## When to Use
- [Trường hợp 1]
- [Trường hợp 2]

## Instructions
1. [Bước 1]
2. [Bước 2]
3. [Bước 3]

## Examples

**Example 1: [Tên]**
Input: ...
Output: ...

## Advanced (Optional)
For [topic], see [reference.md](reference.md)
```

## 7. Quản Lý và Sử Dụng Skills

### Xem Skills Đang Có

**Cách 1: Hỏi Claude**

```
What skills are available?
```

**Cách 2: Kiểm tra thư mục**

```bash
# Personal skills
ls ~/.claude/skills/

# Project skills
ls .claude/skills/
```

### Vị Trí Lưu Skills

| Loại     | Đường dẫn           | Ai dùng được      |
| -------- | ------------------- | ----------------- |
| Personal | `~/.claude/skills/` | Chỉ bạn           |
| Project  | `.claude/skills/`   | Cả team (qua Git) |
| Plugin   | Cài qua plugin      | Tùy plugin        |

### Chia Sẻ Skills Với Team

```bash
# 1. Tạo skill trong project
mkdir -p .claude/skills/team-skill
# ... tạo SKILL.md

# 2. Commit vào Git
git add .claude/skills/
git commit -m "Add team skill for [purpose]"
git push

# 3. Team members pull về
git pull
# Skills tự động available!
```

### Cập Nhật Skill

```bash
# Edit trực tiếp
code ~/.claude/skills/my-skill/SKILL.md

# Restart Claude Code để apply changes
```

### Xóa Skill

```bash
rm -rf ~/.claude/skills/my-skill
```

## 8. Best Practices

### DO ✅

1. **Giữ Skills tập trung một mục đích**

   - ✅ "PDF form filling"
   - ✅ "Git commit messages"
   - ❌ "Document processing" (quá rộng)

2. **Viết description cụ thể với trigger words**

```yaml
description: Analyze Excel spreadsheets, create pivot tables.
  Use when working with Excel files, .xlsx, or spreadsheet analysis.
```

3. **Dùng ví dụ cụ thể thay vì giải thích trừu tượng**

```markdown
**Input:** Added user authentication
**Output:** feat(auth): implement user authentication
```

4. **Giữ references ở 1 level (không nested quá sâu)**

```markdown
# SKILL.md

See [reference.md](reference.md) ✅

# Không nên:

# SKILL.md → advanced.md → details.md → info.md ❌
```

5. **Test với các tasks thực tế**

### DON'T ❌

1. **Không giải thích những gì Claude đã biết**

```markdown
❌ "PDF là định dạng file..."
✅ (Bỏ qua, Claude biết rồi)
```

2. **Không dùng thông tin time-sensitive**

```markdown
❌ "Nếu trước tháng 8/2025, dùng API cũ..."
✅ "Dùng v2 API. Legacy v1 deprecated."
```

3. **Không đưa ra quá nhiều lựa chọn**

```markdown
❌ "Có thể dùng pypdf, pdfplumber, PyMuPDF, pdf2image..."
✅ "Dùng pdfplumber. Cho scanned PDFs, dùng pdf2image với pytesseract."
```

4. **Không dùng Windows-style paths**

```markdown
❌ scripts\helper.py
✅ scripts/helper.py
```

5. **Không viết SKILL.md quá 500 dòng**
   - Nếu quá dài → tách ra files riêng

### Mức Độ Chi Tiết Phù Hợp

| Loại Task                      | Mức độ chi tiết                | Ví dụ                |
| ------------------------------ | ------------------------------ | -------------------- |
| **Flexible** (nhiều cách đúng) | Hướng dẫn chung                | Code review, writing |
| **Semi-structured**            | Template + cho phép điều chỉnh | Report generation    |
| **Critical** (dễ lỗi)          | Script cụ thể, từng bước       | Database migration   |

## 9. Ví Dụ Thực Tế

### Ví Dụ 1: Commit Message Helper (Đơn giản)

```yaml
---
name: commit-message-helper
description: Generate clear commit messages from git diffs. Use when writing commit messages or reviewing staged changes.
---
# Commit Message Helper

## Quick Start

1. Run `git diff --staged` to see changes
2. Generate commit message following format below
## Format
```

<type>(<scope>): <subject>

<body>
````

**Types:** feat, fix, docs, style, refactor, test, chore

## Examples

**Input:** Added login validation
**Output:**

```
feat(auth): add login form validation

- Add email format validation
- Add password strength check
- Display error messages
```

**Input:** Fixed date display bug
**Output:**

```
fix(ui): correct date formatting in reports

Use UTC timestamps consistently across all report pages
```

`````

### Ví Dụ 2: Code Review Skill (Có giới hạn tools)
````yaml
---
name: code-reviewer
description: Review code for best practices and potential issues. Use when reviewing code, checking PRs, or analyzing code quality.
allowed-tools: Read, Grep, Glob
---

# Code Reviewer

## Instructions

1. **Read** target files using Read tool
2. **Search** for patterns using Grep
3. **Find** related files using Glob
4. **Provide** detailed feedback

## Checklist

- [ ] Code organization
- [ ] Error handling
- [ ] Security concerns
- [ ] Test coverage
- [ ] Performance

## Output Format
```markdown
## Summary
[Overall assessment]

## Issues Found
1. [Issue] - [File:Line] - [Severity]

## Recommendations
1. [Specific suggestion]
```
`````

### Ví Dụ 3: Project-Specific Skill (Phức tạp)

````yaml
---
name: blog-cms-development
description: Development guidelines for Blog CMS project. Use when working on React frontend, FastAPI backend, or Supabase database tasks.
---

# Blog CMS Development Guide

## Tech Stack

- **Frontend:** React + Vite + TailwindCSS
- **Backend:** FastAPI + SQLAlchemy
- **Database:** Supabase (PostgreSQL)

## Quick Commands
```bash
# Frontend
cd frontend && npm run dev

# Backend
cd backend && uvicorn app.main:app --reload
```

## Code Standards

### React Components
- Use functional components with hooks
- File naming: PascalCase.jsx
- One component per file

### FastAPI Endpoints
- Use Pydantic schemas for validation
- snake_case for functions
- Include docstrings

## Common Patterns

See [patterns.md](patterns.md) for:
- Authentication flow
- API error handling
- Database queries
````

## 10. Troubleshooting

### Claude Không Dùng Skill

| Vấn Đề                | Giải Pháp                                           |
| --------------------- | --------------------------------------------------- |
| Description quá chung | Thêm trigger words cụ thể                           |
| File path sai         | Kiểm tra `~/.claude/skills/` hoặc `.claude/skills/` |
| YAML syntax lỗi       | Kiểm tra `---` đầu và cuối, không dùng tab          |

**Debug:**

```bash
# Kiểm tra file tồn tại
ls ~/.claude/skills/my-skill/SKILL.md

# Xem nội dung đầu file
head -n 15 ~/.claude/skills/my-skill/SKILL.md

# Chạy Claude Code với debug
claude --debug
```

### Skill Load Nhưng Không Hoạt Động

| Vấn Đề                    | Giải Pháp                                        |
| ------------------------- | ------------------------------------------------ |
| Scripts không chạy được   | Thêm execute permission: `chmod +x scripts/*.py` |
| Thiếu dependencies        | List rõ trong SKILL.md, kiểm tra đã install      |
| File paths dùng backslash | Đổi sang forward slash `/`                       |

### Nhiều Skills Xung Đột

**Giải pháp:** Viết description cụ thể hơn

```yaml
# ❌ Xung đột
skill-1: description: For data analysis
skill-2: description: For analyzing data

# ✅ Phân biệt rõ
skill-1: description: Analyze sales data in Excel. Use for sales reports, pipeline analysis.
skill-2: description: Analyze log files and system metrics. Use for debugging, monitoring.
```

## 11. Checklist Trước Khi Hoàn Thành

### Core Quality

- [ ] `name` đúng format (lowercase, hyphens, max 64 chars)
- [ ] `description` cụ thể + có trigger words
- [ ] SKILL.md dưới 500 dòng
- [ ] Không có thông tin time-sensitive
- [ ] Terminology nhất quán
- [ ] Có ví dụ cụ thể

### Structure

- [ ] File references chỉ 1 level deep
- [ ] Dùng forward slash cho paths
- [ ] Files bổ sung có Table of Contents nếu >100 dòng

### Testing

- [ ] Test với request thực tế
- [ ] Claude tự động trigger skill khi hỏi câu liên quan
- [ ] Output đúng như mong đợi

## Tổng Kết

### Workflow Tạo Skill

```
1. Xác định task lặp lại cần skill
          ↓
2. Chọn vị trí: ~/.claude/skills/ hoặc .claude/skills/
          ↓
3. Tạo thư mục + SKILL.md
          ↓
4. Viết: name + description (quan trọng nhất!)
          ↓
5. Viết: Quick Start + Instructions + Examples
          ↓
6. Test với Claude Code
          ↓
7. Iterate dựa trên kết quả
```

### Key Takeaways

1. **Description là quan trọng nhất** - quyết định Claude có tìm thấy skill không
2. **Ngắn gọn = Tốt** - chỉ viết những gì Claude chưa biết
3. **Test thực tế** - không assume, phải thử
4. **Iterate** - skill tốt nhất đến từ việc cải tiến liên tục
